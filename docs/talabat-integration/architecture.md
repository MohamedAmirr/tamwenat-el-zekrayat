## Doctypes

- **`Talabat Settings`** (Single) — `client_id`, `client_secret` (Password), `chain_id`, `environment` (Sandbox/Production). All four opaque-value fields set `ignore_xss_filter: 1` (see `frappe-conventions.md`). `get_base_url()` resolves the right host for the current `environment`.
- **`Talabat Vendor`** — registry of Talabat outlets/vendors. `vendor_id` (unique, `autoname: field:vendor_id`), `vendor_name`, `is_active`.
- **`Talabat Product Mapping`** — one row per (vendor, Talabat SKU) mapped to an ERPNext Item. Identity is the SKU+vendor pair (the stable thing each row represents), via a custom `autoname()` controller method: `name = f"{vendor}::{talabat_sku}"` — `::` because a plain `-` genuinely collides (item codes and Talabat vendor/chain IDs are hyphen-heavy; see `frappe-conventions.md`'s autoname bullet). `validate()` rejects `::` appearing in either field, enforcing the invariant the naming scheme depends on. Secondary (item, vendor) uniqueness is a hidden `item_vendor_key` field — a fixed-length SHA-256 hash of the pair (`compute_item_vendor_key()`; not a joined string, and not a raw JSON encoding either — that first attempt overflowed the field's length once non-ASCII item codes were involved, since `frappe.as_json`'s default `ensure_ascii=True` escapes each non-ASCII char to `\uXXXX`), computed in `before_save()`, with a DB-level unique index and a pre-existing-row backfill patch (`patches/v0_0/`) that imports the same `compute_item_vendor_key()` function so the two never drift apart. `talabat_sku` is intentionally separate from `Item.item_code` (Talabat's own `sku` is merchant-assigned per its API, not guaranteed to match). `sync_status`/`last_synced_on`/`last_error` track push-to-Talabat sync outcomes (not yet implemented — see #6).

## API layer (`talabat_integration/api/`)

- **`auth.py`** — `get_access_token()` (cached per-environment via `frappe.cache()`, refreshed with a safety buffer before real expiry), `invalidate_access_token()` (forces a fresh fetch after a 401). Also owns `_request()`, the one shared helper wrapping `requests` with a timeout and clean network-error handling — everything else routes through it, nothing else calls `requests` directly.
- **`client.py`** — `talabat_request(method, path, **kwargs)`: **the single choke point for every Talabat endpoint.** Injects the bearer token, retries exactly once on a 401 (via `invalidate_access_token()` + refetch), then raises if the retry also 401s. Returns the raw response as-is for anything else (200/4xx/5xx) — callers check `response.ok` themselves, since different endpoints use different success codes.
- **`catalog.py`** — whitelisted methods for Talabat's catalog. Currently: `get_vendor_products(vendor)`, fetching up to 500 products (Talabat's page-size cap) for a vendor, used to help pick a `talabat_sku` when creating a mapping; `get_vendor_catalog_page(vendor, page, page_size)`, one live catalog page (page and page_size both clamped/validated - page_size user-chosen on the mapping page, clamped to Talabat's 1–500 spec limit) cross-referenced against local `Talabat Product Mapping` rows for that page's SKUs only, for mapped/not-mapped status per row; `get_vendor_mapped_items(vendor)`, the vendor's full `{item: talabat_sku}` mapping map (fetched once per vendor selection by the client, not per page, to keep already-mapped Items out of the item picker without resending the whole list on every page fetch); and `upsert_mapping(vendor, talabat_sku, item)`, the get-or-create behind the mapping page's inline item picker. Does not persist anything Talabat returns (no stored title/price anywhere in this app) — catalog data is always live/display-only.

## Client-side

- **`talabat_integration/doctype/talabat_product_mapping/talabat_product_mapping.js`** — a "Fetch from Talabat" flow: once `vendor` is set, calls `get_vendor_products`, offers the result in an Autocomplete dialog to fill `talabat_sku`. Fails gracefully (manual entry always still works) if the vendor has nothing yet or the fetch errors. The Autocomplete option label (`sku — title`) escapes both Talabat-sourced fields (`frappe.utils.escape_html()`) before interpolating, since Frappe's Autocomplete control renders each option's label via `.html()` with no escaping of its own and `talabat_sku`/catalog `title` are intentionally not XSS-sanitized server-side.
- **`page/talabat_catalog_mapping/talabat_catalog_mapping.js`** — the Talabat Catalog Mapping page (System Manager only): a `Talabat Vendor` filter drives a `RemoteDataGrid` of the live Talabat catalog (via `get_vendor_catalog_page`, user-selectable rows-per-page) with an inline editable Item Link column (`confirm_changes: true`) that saves through `upsert_mapping`. `get_vendor_mapped_items(vendor)` is fetched once per vendor selection (not per page) to keep already-mapped Items out of the Item picker; a per-vendor request-sequence guard discards a stale response from a superseded vendor selection. Its **Add manual mapping** action provides the fallback for a SKU not returned by the live catalog; a **Refresh** secondary action re-fetches the current vendor's catalog (bypassing the change-guard) to recover from a failed load. Status (Mapped/Not Mapped) is computed client-side from the item's presence and updated in place via `RemoteDataGrid.update_cell()` after a save — no full-grid refetch. Clearing the Item cell to save an empty value is blocked client-side with a toast (unmapping isn't supported from this page). Every toast that interpolates a Talabat-sourced or user-typed value (SKU, Item) escapes it first (`frappe.utils.escape_html()`) since `talabat_sku` is intentionally not XSS-sanitized server-side (`ignore_xss_filter: 1`).
- **`workspace_sidebar/talabat_integration.json`** — Desk navigation for this module. It intentionally exposes the catalog page, vendors, and settings, but not the underlying `Talabat Product Mapping` DocType; the DocType remains the data model behind the catalog page.
- **`public/js/remote_data_grid.js`** (`frappe.ui.RemoteDataGrid`) + **`public/css/remote_data_grid.css`** — generic, reusable paginated table (no Talabat-specific logic): `{wrapper, columns, fetch_page(page_number, page_size), on_change, on_error, page_size, page_size_options, confirm_changes}`; columns may set `editable: "Link"` with an optional per-column `get_query(row)` to filter that column's Link dropdown. Renders a rows-per-page selector + Prev/Next footer, guards against stale out-of-order page responses, and gives callers an `on_error` hook while showing a generic failed-load state. `confirm_changes: true` switches an editable cell from auto-save-on-change to an explicit save button (Enter also commits, Escape reverts); `update_cell(row, fieldname, value)` lets a caller update one row's derived/read-only column display (e.g. a computed "status" column) after a save, without re-fetching/re-rendering the whole page. It uses Frappe Link controls and button/toast primitives. Its component-scoped CSS uses Frappe variables only; Talabat page layout lives separately in `public/css/talabat_catalog_mapping.css`.

## Conventions specific to this app (see `frappe-conventions.md` for the general Frappe rules)

- Never call `requests` directly for a Talabat endpoint — always through `client.talabat_request()`.
- Never store a field's worth of data fetched live from Talabat (titles, prices, catalog contents) — display it, don't persist it, unless a future issue explicitly decides otherwise.
- Opaque external identifiers/secrets (`client_id`, `client_secret`, `chain_id`, `talabat_sku`) need `ignore_xss_filter: 1`. The one exception is a field that is *itself* the entire autoname source and can never be edited after creation without changing the record's identity — e.g. `Talabat Vendor.vendor_id` (`autoname: field:vendor_id`), where `_sync_autoname_field` reverts any edit anyway, so the sanitizer never gets a meaningful chance to run. This exception does **not** extend to a field that merely contributes to a `format:`/custom `autoname()` alongside other fields (like `talabat_sku`) — `name` isn't recomputed on update for those, so an edit to the field goes through the sanitizer unprotected unless it has the flag. Verified the hard way: #19 initially over-generalized this and had to add the flag back.
